# site-safety-vlm

건설·산업 현장 이미지·영상에서 (1) PPE(안전모·안전조끼) 착용 상태와 (2) 불안전 행동을 판정하는
소형 VLM을 맥(Apple Silicon)에서 LoRA/QLoRA로 파인튜닝하고, 검증 · 규정 근거 · 리포트 단계를
**고정 파이프라인(A) / 싱글 에이전트(B) / 멀티 에이전트(C)** 로 구현해 같은 평가셋으로 비교하는 개인 프로젝트.

> 상태: 0 - 1단계 진행 중 (데이터 준비). 모델 학습과 A / B / C 비교는 아직 시작하지 않았다.
> 결과 표는 실험이 끝난 뒤 채운다. 수치가 없는 항목은 아직 측정하지 않은 것이다.

## 흐름

데이터 준비 → zero-shot baseline → LoRA/QLoRA 학습 → 비교 · 어댑터 확정 → 영상 추론(PPE · 행동 후보)
→ 검증 · 규정 근거 · 리포트 (A / B / C) → 점검 리포트 → A/B/C 비교

전체 계획: `docs/PLAN.md`, 실험 기록: `docs/experiments.md`

## 데이터와 라이선스

데이터 · 영상 원본은 레포에 올리지 않는다. 출처 · 라이선스 · 실제 장수는 `data_sources.md`에 기록한다.
일부 데이터는 비영리 라이선스(CC BY-NC)라 학습 · 포트폴리오 목적으로만 쓰고 가중치는 공개하지 않는다.

## 지금까지 한 것 (2026-11-18 기준)

- 데이터: PPE는 CHVG + Roboflow safety 통합 분할(3,922장, pHash 그룹 단위, 분할 간 겹침 0), 행동은 Safe and Unsafe Behaviours 클립 691개(8클래스) 전부 내려받음. SteelBench는 공개되지 않아 쓰지 않는다.
- 라벨: 두 PPE 데이터를 통일 클래스로 변환하고 정답 JSON으로 바꿨다. 변환 라벨 표본 점검과 평가셋(valid + test 784장) 점검은 Claude가 했고 사람의 독립 확인이 아니다. 평가셋 정답 오류율은 1%에서 5% 사이로 추정하며(근거 약함), 평가 결과표에는 이 범위를 같이 적는다. 자세한 내용은 `eval/label_audit.md`, `eval/label_noise.md`.
- 행동 클립: 제공된 train / test를 유지하고 train에서 dev를 떼어 jsonl로 변환했다. 해상도와 fps를 낮춘 캐시를 만드는 도구가 있다(`sitesafe.vision.clips`).
- 환경: mlx-vlm 0.8.0에서 이미지 · 영상 추론과 영상 클립 입력 학습이 동작함을 확인했다. 단 학습 정확도는 아직 없다. 실제 클립으로 재 본 메모리 사용량과 막힌 점은 `docs/experiments.md`.
- 규정: 산업안전보건기준에 관한 규칙(시행 2026-03-02)에서 조문 10개를 발췌했다(`data/rules/`). 법적 효력이 없는 참고 근거이고, 안전조끼 착용을 요구하는 조문은 이 규칙에서 찾지 못했다.

## 한계 (진행하면서 갱신)

- 행동 데이터는 한 공장에서 수집된 영상이라 다른 현장으로의 일반화를 주장하지 않는다.
- 합성 영상(SynthSite)은 파이프라인 동작 점검용이며 정확도 평가에 쓰지 않는다.
- 구역별 필수 장비(`configs/zones.yaml`)와 행동 클래스 → 규정 매핑(`configs/behavior_rules.yaml`)은 가정값이다.
- 행동 클립에는 카메라 · 촬영일 정보가 없어 train / test 사이 누수를 점검하지 못했다(프레임 유사도로도 구분되지 않음). 행동 dev는 클립 무작위 분리라 낙관적일 수 있고, train과 test의 클래스 분포가 많이 다르다.
- 평가셋 정답은 사람이 만든 것이 아니라 공개 라벨에서 규칙으로 변환한 것이고, 오류가 남아 있다. 평가셋에는 현장이 아닌 이미지(교실, 거리)도 섞여 있다.
- 규정 조문은 법적 효력이 없는 참고 근거이며, 행동 클래스와 조문의 대응은 가정값이다.
